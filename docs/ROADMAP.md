# Roadmap

Этапы идут по порядку; каждый заканчивается рабочим состоянием и зелёным CI. Отмечай `[x]` по мере выполнения.

## Этап 0 — Каркас
- [x] Cargo workspace со всеми крейтами из DESIGN.md §3 (пустые, компилируются)
- [x] CI (GitHub Actions или GitLab CI): fmt, clippy `-D warnings`, test на Linux, Windows, macOS
- [x] `app`: пустое окно eframe; `cli`: `--version`
- [x] Базовый `tracing`-логгинг

## Этап 1 — Модель и формулы
- [ ] `model`: Resource, Tag, Machine (params, formulas, constants), Recipe (chance, catalysts), Pattern, accuracy, единицы
- [ ] `expr`: парсинг и компиляция выражений, переменные, именованные функции, понятные ошибки
- [ ] `packs`: загрузка пака из каталога, `pack.toml`, зависимости, слои/оверлеи, валидация ссылок
- [ ] Ручной мини-пак ванилы (печь, несколько рецептов) для тестов

## Этап 2 — Солвер и CLI
- [ ] `graph`: ноды Machine/Source/Output/Hub/Note, порты, связи, сети; JSON-формат с `format_version`
- [ ] `solver`: сведение к Process, LP режима анализа, загрузка, излишки/дефициты, баланс сетей
- [ ] `cli solve <schema.json>` — печатает потоки, загрузку, проблемы
- [ ] Сценарии 1 и 4 из DESIGN.md §11 как тесты

## Этап 3 — GUI MVP
- [ ] Холст на egui-snarl: создание/удаление нод, связи, перемещение
- [ ] Инспектор: машина, рецепт, параметры, количество
- [ ] Пересчёт на каждое изменение; цвета состояния, потоки на связях
- [ ] Нижняя панель: баланс, сети, проблемы
- [ ] Сохранение/открытие файла, undo/redo, выбор единиц

## Этап 4 — Импорт из JAR
- [ ] Выбор инстанса/папки `mods/`, чтение JAR
- [ ] Рецепты ванилы из JSON, lang (en/ru), текстуры предметов → атлас
- [ ] Кэш импорта, отчёт (неизвестные типы рецептов)
- [ ] Браузер предметов/рецептов с иконками и поиском, drag-n-drop на холст

## Этап 5 — Плагины
- [ ] `plugin`: хост Luau, песочница, манифест, лимиты, обработка ошибок
- [ ] API v1: импортёры рецептов, функции для формул, типы нод, транспорт, сети, валидаторы
- [ ] Ванилла переносится в `plugins/vanilla` (проверка, что API достаточно)

- [ ] Сценарий 2
